# 教学层：讲解模式 · 自测考核

参考实现：assets/example-diesel/src/94_learn.js（~230 行，可整片移植）。
这是"技术演示"与"课件"的分界线——没有教学层的仿真只能被看，有教学层的仿真
能教人。M 档及以上默认配备。

## 1. 讲解模式（导览引擎）

数据即内容：一张站点表驱动全部行为。

```js
STOPS=[{ z:'配气机构', e:'VALVETRAIN',
  view:'valve',                      // 复用视角预设（fly 过渡）
  hl:['camshaft','tappet','rocker'], // 本站高亮的 partId 集
  dur:18,                            // 自动播放停留秒数
  on(){ ST.rpm=750; ... },           // 可选：进站时布置工况
  txt:'下置<b>凸轮轴</b>由正时齿轮以曲轴<b>一半转速</b>驱动……' }]
```

- 底部字幕卡：站号/标题/解说词/进度点（可点跳站）/上一站·暂停·下一站。
  自动推进用主循环里 `applyLearn(dt)` 累计计时，手动切站清零。
- **多零件高亮**用独立的琥珀色克隆材质缓存（TCACHE），与悬停的青色高亮
  （HLCACHE）分开——讲到哪里亮哪里，同时悬停仍可用。清理函数要把两套都还原。
- 进入时快照 {rpm, load, flow…}，退出恢复；与拆解/考核**互斥**（互相调用对方
  的 exit，两个方向都要接）。
- **解说词写作要求**：每站 2–4 句；指着看得见的东西讲（配合 hl 集）；给具体
  数字（转速比、升程、温度）；把"为什么"讲出来（如"这正是四冲程的机械本质"）；
  末站引导用户去自由探索/拆解/考核。这段文字是教学价值主体，禁止空话。

## 2. 考一考（自测引擎）——考题零人工编写

核心洞察：**信息卡 DB 本身就是题库**。零件档案写得好，考题就自动是好题：

- **找零件题**（4 题）：从 PICKABLE∩DB 随机抽件，出示中文名+英文名+功能提示，
  用户在 3D 场景里点击作答（复用悬停拾取：click 时校验 hovering 的 partId）。
  答错 1 次提示"这是「××」再找找"，2 次后公布答案（高亮+镜头飞过去）。
- **功能选择题**（4 题）：随机抽件高亮并把镜头飞到包围盒前，选项 = 该件的
  fn + 另外 3 件的 fn（打乱），点击作答，答错时标出正确项。
- 计分 + 错题回顾（列出零件名，引导回去悬停复习）；"再来一轮"重新随机——
  每轮题目都不同。
- 出题只依赖 DB 与 PICKABLE，**换一台机器零改动**。这也反过来抬高了 DB 的
  质量要求：fn 字段必须写得能当选择题选项用（独立成句、指向明确、不互相雷同）。

## 3. 移植清单

1. 复制 94_learn.js，替换 STOPS 内容（站点数 6–10，覆盖每个主要子系统）。
2. 主循环加 `applyLearn(dt)`；tdEnter 里加对 tour/quiz 的互斥退出。
3. 左栏插「教学 LEARN」面板（▶ 讲解模式 G / ✎ 考一考 Q），操作引导补一行。
4. 验收：脚本遍历全部站点（字幕非空、高亮数>0 的站占多数）、考核全对路径
   得满分、错答路径能推进、退出后 TLIT 为空、与拆解互斥两方向都生效。
